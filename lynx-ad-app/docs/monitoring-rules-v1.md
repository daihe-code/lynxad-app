# 盯盘优化规则与详情

本版将计划级配置分为目标 ROI、消耗保护与增长机会三个分区。八个字段独立持久化到 `OptimizationPolicy.rules`，保留原版本 JSON 的读取兼容。用户保存新版规则时，原自动预算、ROI、恢复、素材增删与付费生成权限全部清除；仅明确选择 AUTO_PAUSE 时允许本计划的 DAILY_LIMIT 暂停。独立任务终止、恢复和追加预算仍通过原有人工确认流程。

- 规则保存与详情查询不调用千川或引擎接口；按租户及计划读取，使用 expectedVersion 防止覆盖。仅失效当前计划的旧判断，不重置其他计划。
- 新版每分钟采集真实当天报表；消费提醒和保护使用可核实的新鲜数据。缺净成交字段时不填零，消耗完整时仍可单独保护。报表不完整、过期或跨日时不自动暂停。
- ROI 判断需三个连续完整小时，预留至少 60 分钟成交回补。首次积累、缺失窗口和断档均等待数据。跑飞只用真实累计快照差分，要求观察区间连续；不从小时数据合成分钟数据，跑飞仅提醒。
- 增长仅生成待确认建议，受单次与每日累计金额约束。现有素材、任务与商品诊断能力不会因保存新版规则自动获得写入权限。本版不把全部行业诊断规则声明为已接入。
- 每类建议按计划、版本和北京时间日期去重。规则保存/关闭形成审计事件；平台写入沿用原有幂等日志、账户租约和只读回查。关闭优化允许保留尚未核实的已提交操作，不重复写入、不宣称成功。
- V50 新增每日有效时长表。只累计连续不超过 90 秒、成熟 ROI 数据完整且未受限的检查区间；关闭、暂停、断档、数据缺失与结果核实期间不计。历史未记录时长不补造。
- 详情分成成效、当前处理与工作记录。风险处理导航至现有计划/素材/调控面板，由用户确认；独立任务状态单独读取，不能把主计划暂停视为任务全部终止，也不把任务消耗再叠加到计划总消耗。
- 未建立可靠同口径效果对比与损失估算时，ROI 改善和减少损失金额显示“—”。没有真实任务完成记录时显示 0，不使用示意值。没有逐字段来源更新时间时不虚构“成交最后更新”时间。

接口：GET `.../optimization/rules`、PUT `.../optimization/rules`（rules、enabled、expectedVersion），GET `.../optimization/details`（today、category、days、pageNum、pageSize）。原接口和历史记录继续保留。
