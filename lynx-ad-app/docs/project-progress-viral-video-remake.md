## 新需求：爆款视频复刻

### 用户目标

用户提供一个参考视频，选择自己的商品及替换后的出镜人物，生成一条借鉴参考视频节奏和表达结构的新视频。目标是保留可借鉴的创作结构，不复制原视频的具体人物、逐字台词、音乐或画面。

### 项目现状

- 已有商品选择、商品参考信息、异步视频生成、任务进度、素材入库、审核/同步与计划使用流程。
- 现有创建流程支持智能生成、素材库选择和本地上传；当前文档没有描述“上传参考视频并抽取分镜/表达结构，再用另一商品和人物生成”的完整流程。
- 现有生成依赖 AI 引擎。复刻能力需要先确认引擎是否有视频理解、镜头切分、语音/字幕提取及参考结构生成接口；缺少的部分需要新增引擎能力或服务。
- 生成扣积分应复用现有积分钱包与生成任务的幂等/失败退还机制，具体计费数值另行确认，不在本需求记录中臆定。

### 建议的第一版流程

1. 用户提供有权使用的参考视频：本地上传，或粘贴抖音分享链接由服务端下载导入（见“链接导入（粘贴链接）”一节）。
2. 用户选择坤境商品，并选择出镜方式：AI 虚拟人物，或使用已获授权的人物素材。
3. 系统分析视频时长、分段、开头钩子、镜头景别/运动、场景、字幕主题、口播要点和节奏，输出可编辑的分镜与文案草案。
4. 用户确认改写后的脚本、分镜、商品卖点和人物设定后，再启动视频生成；原视频的口播和配乐不直接复用。
5. 生成后检查商品展示、文案事实、人物替换、视频规格和平台审核状态。用户确认后存入素材库，再沿用现有投放流程。

### 必须保留的约束

- 要求用户确认其有权提交和参考原视频；保存来源、分析版本、生成任务及确认记录。
- 不复刻未经授权的可识别真人面孔/声音，不直接搬用原视频台词、商标或音乐。用户提供的人物形象须有相应授权。
- 商品卖点来自用户选择的商品资料及可核实素材，不从参考视频推断该商品的功能、效果、价格或承诺。
- AI 生成任务按现有积分规则先预留、幂等提交、按结果结算；重复轮询不得重复扣费，失败按现行规则释放预留。
- 生成结果默认进入待确认素材，不自动发布广告。

### 待确定事项

- 视频时长、画幅及每次生成的版本数量。
- 人物替换首版仅支持 AI 虚拟人物，还是同时支持上传且已授权的替换人物素材。
- 保留参考视频结构的程度，以及可编辑的镜头/脚本范围。
- 复刻任务的积分价格、生成失败的退款策略及并发上限。
- 是否需要把分析草案单独保存，支持稍后继续生成。

## 爆款复刻首版实现

- 入口为「素材中心 → 视频库 → 爆款复刻」。参考视频可本地上传（最多 120 秒），或粘贴抖音分享链接由服务端下载导入；从当前千川账户选商品，补充真实商品事实，选择方舟预置虚拟人像。成片为 15 或 30 秒竖屏，每次一条。
- 引擎根据实测镜头与抽样关键帧拆解结构。有已配置的语音识别模型时也参考口播结构。分镜生成后等待用户编辑或确认标题、画面、旁白和字幕。参考片的画面和声音不进入成片。
- 应用侧只在确认生成时按现有单条视频价格预占积分。成片就绪后结算，明确失败释放预占，未知回执保留待核对。用户可在任务记录中续看进度，预览后可保存到素材库。
- 运行时需要应用 Flyway V59、引擎 Alembic 0025、同版本的引擎 API 和独立商品复刻 Worker，以及既有 OSS、模型和渲染器配置。引擎未就绪时，应用入口显示服务不可用。

## 链接导入（粘贴链接）

- 入口与流程：复刻弹窗步骤 0 可在「本地上传 / 粘贴链接」之间切换。链接模式粘贴抖音分享链接或视频 URL（`v.douyin.com` 短链、`douyin.com/video/xxx`、`iesdouyin.com` 分享页）；前端只做格式校验，提交时服务端下载并导入，规格不符时报错、不创建任务。
- 主下载器：开源免登录 H5 路由（`DouyinLinkVideoDownloader`）。解析分享短链，两次请求 iesdouyin 分享页取得 ttwid 设备 Cookie，从内嵌 `videoInfoRes` JSON 取播放地址，`playwm` 换 `play` 去水印，下载后用 ffprobe 校验：时长 4–120 秒、横屏 16:9 或竖屏 9:16、短边 720–1440 像素、长边不超过 2560 像素、视频不超过 200 MB。
- 备用下载：自托管 Docker 的 Evil0ctal Douyin_TikTok_Download_API，仅当配置了 `lynx.ad.remake-link.download-api-base-url` 与 `download-api-path` 时启用；主路由失败后才尝试。备用接口只返回异步 `task_id` 而无视频地址时明确报错。
- 同一路径：下载成功后复用现有上传、分片、完成登记流程（`VideoRemakeService.importLink`），与本地上传走同一素材注册、同一存储、同一复刻管线入口，不重复复刻逻辑。来源记录在 `creative_video_remake_upload`（Flyway V62 新增 `source_url`、`source_platform`、`download_method`）。
- 错误情形：链接不可达、需登录、私密或已删除、规格不符时返回明确错误，不静默替换其他视频，不编造结果。
- 配置：环境变量 `LYNXAD_REMAKE_LINK_DOWNLOAD_API_BASE_URL`、`LYNXAD_REMAKE_LINK_DOWNLOAD_API_PATH`、`LYNXAD_REMAKE_LINK_DOWNLOAD_API_KEY`、`LYNXAD_FFPROBE_PATH`（默认 `ffprobe`）；备用接口地址与路径留空时不启用，需按自托管实例的 `/docs` 填写，尚未部署真实实例。
- 接口与代码：`POST /api/v1/creative/video-remakes/uploads/link`（`VideoRemakeController`）；前端 `VideoRemakeDialog.vue`、`videoRemakeApi.ts` 的 `importRemakeLink`。单测见 `DouyinLinkVideoDownloaderTest`（纯函数单测，不发网络请求）。
- 仍需注意：链接导入成功后若创建任务失败，已导入的链接资产会残留（与本地上传重试时重新上传的行为一致）。
