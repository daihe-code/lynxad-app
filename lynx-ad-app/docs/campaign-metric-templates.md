# 计划列表指标模板

计划列表右上角提供两个系统模板。模板只影响统计展示、排序及 CSV 导出，不改变计划的投放方式、预算或优化目标。

概览卡片和列表表头的指标名称带虚线下划线，悬停或键盘聚焦时显示指标含义；ROI 指标同时说明计算公式。表头点击排序保留。

| 模板 | 概览及列表字段 |
| --- | --- |
| PAYMENT / 整体支付ROI目标 | 整体消耗(元)、整体成交订单数、整体成交金额(元)、整体支付ROI |
| NET / 净成交ROI目标 | 整体消耗(元)、净成交ROI、净成交金额(元)、1小时退款率 |

## 查询与数据边界

`GET /api/v1/delivery/plans` 增加 `metricTemplate=PAYMENT|NET`，默认 PAYMENT。响应回传 `metricTemplate`。既有支付字段保留原含义；NET 额外返回 `netGmvYuan`、`netRoi`、`refundRate`，概览对应 `summary.netGmv/netRoi/refundRate`。对比数据的 current/previous 也分别携带三项净成交指标。

NET 从千川 `SITE_PROMOTION_PRODUCT_AD` 指标配置中识别“净成交ROI”“净成交金额”“1小时内退款率”，仅请求当前账户开放且可搭配 ad_id 的字段。每个广告账户、日期区间批量查全部计划，复用分页缓存，不逐计划查询。缓存按灵投租户、授权账户、广告主、日期区间和模板隔离，每次读取缓存前仍检查授权。

平台缺少的字段、无报表、真实的零值分别保留为 null/null/0。不得把支付金额、支付ROI或历史快照当作净成交数据。NET 未带日期时查询北京时间当天；新界面始终传所选日期。

## 汇总

概览在筛选完成、分页之前计算。净成交ROI使用汇总净成交金额 / 汇总消耗。1小时退款率采用各计划的平台退款率按整体成交金额加权，单位为百分数；不按计划数简单平均。正成交金额的计划缺少退款率，或缺少汇总所需金额时，汇总退款率为 null。无成交金额时不制造百分比。缺少订单数不影响已经返回的净成交金额和消耗汇总。

## 前端一致性

字段和数值在同一请求成功后一起切换；过期响应不能覆盖新选择。失败保留上次成功的字段和数据，允许刷新或重新选择模板重试。CSV 固定采用导出开始时的模板，逐页核对响应模板。浏览器偏好按租户及用户隔离，仅在查询成功后保存。

回归覆盖平台动态字段、缓存隔离、缺失值、零值、范围汇总、净成交排序、金额加权退款率、导出字段顺序及偏好隔离。浏览器用本地接口夹具验证菜单、切换、刷新恢复、排序、导出与异常显示。
