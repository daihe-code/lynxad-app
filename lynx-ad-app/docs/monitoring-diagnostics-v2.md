# 盯盘诊断、确认与复评续作

承接 `monitoring-rules-v1.md`，本次完善三条链路：同对象数据诊断、用户确认处理、实际修改后的可比复评。该续作只提交代码，生产部署需要单独授权。

## 数据与诊断

- 小时数据只接收完整、连续的一小时窗口，保留净成交、支付订单、曝光及点击的真实字段映射；缺字段、负向修订、断档均不补零、不插值。昨天同一时间窗口用于比较，商品与素材只使用当前计划绑定下的报告，不使用素材中心跨计划累计值。
- 覆盖成熟消耗零净成交、ROI 走弱、CTR 走弱、支付订单承接下降、CPC 上升、同口径退款率变化与素材疲劳线索。素材集中度只作为事实，不当成疲劳证明。原因是待核实假设，不是归因结论。
- 分钟消耗加快与成交回传独立：即使净成交数据缺失，仍可记录“消耗加快，成交数据待核对”。该提醒不会自动暂停，也不直接认定跑飞。
- 同一版本、问题类型及对象的开放事件持续更新，不在每轮检查重复通知；证据恢复后关闭建议，未执行不计优化完成。复评中的同对象问题不再重复创建。
- 商品、素材和任务报告采用独立缓存；这些数据失败不阻塞可靠的当天消耗保护。

## 策略登记与当前限制

`lynx.ad.monitoring.strategy-json` 保存策略版本、批准状态、成熟延迟、窗口长度、最小样本、变化阈值与复评时限。空配置为 `candidate-v1`，仅作影子诊断：不会把未校准的阈值变成商家经营建议或有效经营盯盘时长。配置错误启动失败，不悄悄回退为另一套生产阈值。

生产启用需产品与数据验证上述参数，且 `riskModelApproved` 只能在策略批准后启用。仓库中的候选值和测试值不代表已获得业务批准。

当前适配器无法证明当日外部新增预算账本与平台预算瓶颈，明确记录为未核实。因此不会因为 ROI 高就建议加预算。预算确认与正向承诺账本已实现，但真实预算增长仍被这两个证据条件阻止。已验证素材可给出明确对象与单一变化的测试建议，进入原素材流程独立确认；不自动购买生成额度、发布素材或创建追投任务。本次不宣称已覆盖 PRD 的全部 51 个场景。

## 确认与执行

- `GET .../optimization/decisions/{event}/preview` 返回服务端方案与事实摘要；`POST .../confirm` 使用版本和摘要再次确认，不接受客户端自定义动作。当前范围为日消耗保护暂停与有充分证据的预算增长，其他动作仍使用原流程。
- 确认受租户/计划所有权、账户租约、规则版本、当前事实、数据时效及当天边界限制。先持久化一次性确认与预算承诺，再提交平台。结果不明只回读，重试不重复写入。
- 只累计正向新增承诺；明确未发出的预留可释放，已提交、超时与未知结果保留。降预算与独立任务提前停止不会退回当天已承诺金额。
- `POST .../decisions/{event}/track` 为现有编辑流程建立关联。跟踪编号不是执行授权；页面跳转与 API 接受均不计完成。普通计划写入需要业务成功回执和平台实际变化；已投放素材通过服务端工作草稿、原计划、保存完成状态及预期绑定回读一起核实，异步未完成不能计成功。

## 复评与统计

- V51 持久化关联工作草稿、修改前后事实、策略快照、准确的基线窗口、后续观察及结果。进程重启、关闭经营优化后，已执行任务继续核实和复评。
- 调整后从下一个完整小时开始观察，等完整窗口和成交回补，再重新读取原基线以纳入晚到修订；两边字段口径、窗口长度与有效消耗样本必须一致。
- 观察期再次修改设置/商品/素材、缺样本、长时间无有效数据或暂停而无可比投放窗口时，不输出 ROI 改善。可比结果明确标为观察变化，不作因果归因或虚构减少损失金额。
- 有效经营盯盘时长只计全部依赖可用的连续区间，数据受限和影子策略不补记时长；日消耗保护仍可独立运行。已核实主计划暂停的数量不等于独立任务风险已经全部处理。

## 验证

新增单元与持久化测试覆盖缺字段/零值差异、窗口连续性、策略限制、跨租户、陈旧确认、确认重放、超时只回读、正向承诺预留、规则版本变化、异步素材回读和不可靠效果比较。持久化测试在独立 H2 MySQL 模式应用真实 V28/V29/V51 脚本；它不代替生产 MySQL 的部署前迁移验证。
