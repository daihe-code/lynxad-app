# 自动盯盘与受限自动执行

App 负责租户授权、千川采集、执行与回查；Engine 负责确定性贡献利润分析、素材诊断和生成。默认关闭，OBSERVE 只生成建议，AUTO_LIMITED 按逐计划授权执行预算、净成交 ROI、启停，以及一键起量、素材追投、素材增删和商品删除。当前规则版本为 `profit-control-v5-generation`。

## 自动素材生成与试投

不再从候选计划复制素材。旧 `materialAdd=true` 不会授权付费生成；旧候选计划列表读取为空，旧商品新增权限读取为false。用户需要在计划运营面板的“自动盯盘”中勾选“诊断后生成新素材”，选择形式、品牌表达偏好、禁止宣传内容、生成预算预留及试投亏损上限，核实商品成本后保存新授权。

“生成完成后自动同步并发布到原计划”默认关闭。关闭时生成后进入待确认状态，可以预览视频或图片、查看诊断和表达方向，再确认发布；显式开启并保存后，后台可继续自动同步、发布和试投。相关记录位于计划盯盘页面，全店中心保留建议与执行历史、通知和记录入口。转投两种模式共享记录、生成限额和素材绑定，不为同一商品创建新的广告计划。

第一版诊断采用可检查的规则：

- 素材不足：当前绑定数量加待验证数量低于授权门槛，补充未覆盖的需求或表达形式。
- 点击下降：最近两个完整成熟日均达到曝光门槛，后一日点击率低于前一日的80%，提出新开头或首图的试验假设，优先沿用原形式。点击下降不证明素材疲劳，也不声称严格单变量实验。
- 转化偏弱：达到点击样本且素材贡献利润为负，探索真实细节、适用条件与选购顾虑的表达。同商品两个或以上素材同时亏损时，暂停该类生成并提示检查价格、规格和承接。
- 视频、图文、商品卡图片只能从用户授权形式中选择。优先参考已有形式和本商品最近试投记录；避免已知亏损的表达风格，并将现有素材及试投反馈传给原生成流程。外部素材目前没有完整视觉风格识别，不能保证只凭报表判断所有内容差异。

生成只使用仍绑定的商品、真实参考图、明确库存和已核实贡献率。价格区间仍作为区间传给引擎，不改写成具体成交价。每商品24小时最多一批、一批一个素材、最多两个待验证素材；每日生成预留额度按转投逻辑计划共享。每次申请先持久化并预留预算，再用同一请求ID交给Engine，返回不明确时回查原请求，禁止创建重复生成任务。

生成完成后复用现有素材导入、上传和图文创建流程；广告写入仍进入原执行日志，独立重读授权、库存、绑定、数据新鲜度、冷却和动作次数，发布后回查所有转投成员。未审核通过不进入试投评价。发布当天的部分数据不计入成熟日；曝光、点击或净成交字段缺失时继续观察，不把无曝光判成失败。每个素材单独计算：`预估试投贡献利润 = 成熟净成交收入 × 已核实贡献率 × (1−退款预留) − 成熟消耗 − 预留生成费用`。

达到样本、成熟日数、订单门槛且上述利润为正时标为“试投达标”，不宣称因果胜出；广告亏损达到试投上限时，只有授权删除且关联计划均能保留足够已审核可投素材，才提交移除绑定。没有删除权限或触及保留条件时通知人工处理。14天仍未达到样本、利润或审核条件时结束本批验证并保留素材。达到试投门槛后，盈利素材仍按原成熟数据规则判断是否追投。

生成、审核、同步、发布、试投与移除均持久化；多实例用数据库租约处理。撤销授权、人工接管或授权版本变化会停止本批后续步骤，已经提交的平台操作继续只读回查。用户可停止本批后续发布与试投管理；这不会撤回已经发出的模型生成请求，也不会删除已发布绑定或素材中心文件。

生成成本目前是管理员配置的预算预留，默认视频30元、图文8元、商品卡3元，**不是模型供应商实际账单，也不是实际扣费硬上限**。原生成流程可能有内部重试；实际成本对账仍需后续接入。平台自主分配流量、报表回补和扫描延迟同样意味着试投亏损线不是即时扣费硬上限。

## 用户入口

1. 顶部“全店盯盘”或投放列表的“全店盯盘”进入 `/monitoring`。计划名称运营面板中的“自动盯盘”可配置单计划。
2. 填写每个绑定商品的广告前贡献率、额外退款预留，并核实资料。贡献率包含货品、履约、平台及其他变动成本，尚未扣广告消耗。
3. 开启盯盘，先用观察模式检查真实数据与利润判断。后台每5分钟采集一次，关闭浏览器不停止采集。
4. 选择自动调控，分别授权预算、ROI、风险暂停和次日恢复，填写预算/ROI范围、单次幅度、冷却时间、每日调整次数。保存时页面明确确认授权。
5. 扩量前在全店中心设置广告账户总日预算上限。未设置时，不自动加预算、降低ROI或恢复投放；减预算和风险暂停可运行。
6. “建议与执行历史”可按账户、计划、日期、处理状态筛选，查看依据、规则/授权版本、拟调整值、提交时间及平台回查值。新建议、成功、结果不明确、采集异常/恢复及人工接管进入右上角站内通知。
7. 手动修改计划会暂停其转投关联计划的自动调控，仍继续观察。全店暂停停止后续自动执行；已经提交的操作继续回查。核查后在中心逐计划“恢复授权”。

## 数据与规则

- 已发布的灵投计划和外部导入计划支持盯盘；暂停计划保留数据，删除计划停止采集，历史仍保留。
- 各物理千川计划独立统计。转投关联传同一逻辑计划ID，商品利润资料按租户、账户、抖音号及商品共享。
- 读取实时计划详情、昨天和今天的小时趋势、今日累计消耗。累计指标不伪造成小时增量。净成交收入缺失时不用支付GMV替代。
- 至少等待60分钟转化回补，要求3–8个连续完整小时窗口及最新成熟窗口，满足最低样本消耗。加量还需最低成交样本；成熟的零成交亏损可触发止损。
- 有效贡献率采用全部已核实商品的最低 `贡献率 × (1−额外退款预留)`。
- `预估贡献利润 = 净成交收入 × 最低有效贡献率 − 消耗`。这是保守估算，不是结算利润。
- 达到当日消耗限额，或成熟窗口亏损达警戒线：按授权暂停。风险暂停不受扩量冷却和每日调整次数限制。
- 连续成熟窗口亏损但未达止损线：授权净成交ROI时小幅上调，否则按权限减预算。
- 连续盈利且利润/消耗至少20%：按权限小幅加预算。控成本且消耗未达日预算一半时，可按权限小幅下调ROI，但保持至少保本净ROI的1.1倍。
- 放量预算下限50元，控成本下限300元；单次调整比例1–20%，冷却60–1440分钟，每日调整/恢复1–10次。自动ROI只支持平台净成交ROI优化目标。
- 次日恢复默认关闭。只有显式授权、由灵投每日限额规则暂停、已跨北京时间日期且达到授权小时、当日消耗低于限额时才恢复。人工暂停、亏损止损不会恢复；转投另一模式运行或状态不明时不能启用。
- 缺失/过期/跨日数据、未核实利润资料、人工接管、版本不一致、当前值变化、账户有未确认操作等均阻止执行。

这些阈值属于产品策略，不是千川官方效果承诺。库存、后续退款及结算成本仍需商家核实。采集与报表存在延迟，风险限额不是平台硬扣费限额，不能保证实际消耗完全不越线。

## 执行与并发

Engine 提案不能直接变成任意平台请求。App 使用固定动作白名单，再独立检查授权、身份、数值、样本、利润资料、新鲜度、冷却与次数；执行前重新读取平台和当日风险数据。素材新增仅接受本地生成记录与已上传素材的来源证明，由App重建固定创意请求，拒绝旧候选复制提案和任意引擎写入JSON。

账户数据库租约串行化 App 多实例自动/手动操作；涉及增加投放能力的操作先读取千川两种模式的完整计划列表，检查所有投放中计划日预算合计。这个上限约束 App 执行时的预算合计，不是账户扣费额度，也不能阻止千川后台另行修改。

转投组锁保护关联变更。`optimization_event` 在平台请求前持久化 EXECUTING。服务重启只读回查已提交事件，不重新写平台。已达到目标值则记录 SUCCEEDED；暂未返回目标值进入 VERIFY_PENDING；超过约3分钟仍不明确进入 UNKNOWN，暂停自动授权并阻止该账户后续自动写。用户可“回查平台”或“人工核查完成”；后者标记 ACKNOWLEDGED，接受当前状态但不宣称原操作成功，需另行恢复授权。

平台认证过期或明确限流的底层现有恢复机制仍适用；通信超时或不明确结果不会重新提交自动动作。历史与站内通知按语义指纹去重，同一成熟窗口的相同提案不重复生成消息。

一键起量、素材追投、素材增删及商品删除已接入自动链路，原有手动入口保留；商品不允许自动增加。搜索抢首屏不纳入自动链路。

## 部署

- App Flyway：MySQL / PostgreSQL 使用各自 V28、V29、V30；V30保存素材生成预留、状态及试投数据。
- Engine PostgreSQL：启动前 `alembic upgrade head`，新增0012、0013；0013为已有安装补建生成请求回执表，开发SQLite自动建表。
- App `LYNX_AI_ENGINE_BASE_URL` 指向Engine；`LYNXAD_MONITORING_API_KEY` 对应Engine `OPTIMIZATION_API_KEY`，仅后端注入。若启用Engine全局API认证，配置App `LYNXAD_ENGINE_API_KEY`。
- App、Engine、数据库需常驻。新链路由App定时采集驱动，不需要既有模拟monitoring worker。多实例共享数据库租约。
- 素材生成复用现有生成队列，生产部署应配置已有Redis队列及生成worker。请求回执保证不重复创建任务；本机无持久队列时，进程在生成中退出可能需要核查原任务，不承诺进程内任务自动恢复。
- Engine可通过 `OPTIMIZATION_GENERATION_RESERVE_VIDEO`、`OPTIMIZATION_GENERATION_RESERVE_IMAGE_TEXT`、`OPTIMIZATION_GENERATION_RESERVE_PRODUCT_CARD` 配置预留单价。改变单价后，旧未提交策略会被拒绝，下一轮重新诊断。
- 本机服务配置在仓库外 `D:/LynxAd-runtime/auto-monitoring.local.properties` 和Git忽略的Engine `.env`。不得提交密钥。
- 未对任何真实计划开启自动执行，开发验证未提交真实广告变更。

## 接口

- `GET/PUT /api/v1/delivery/plans/{id}/optimization`：状态/设置，保存带expectedVersion。
- `POST .../optimization/check`：立即采集已开启计划。
- `GET .../optimization/creative-jobs`：查看转投组共享的生成与试投记录。
- `POST .../optimization/creative-jobs/{job}/review`，`{approved:true|false}`：确认发布或停止后续管理。
- 原 `GET .../optimization/candidates` 保持兼容并返回空列表。
- `GET /api/v1/optimization/center`：跨账户计划分页、汇总及账户上限。
- `GET /api/v1/optimization/history`：租户隔离历史；日期区间最长180天。
- `PUT /api/v1/optimization/accounts/{id}/limit`：账户总日预算上限。
- `POST /api/v1/optimization/hold-all`：停止全店后续自动执行。
- `POST /api/v1/optimization/plans/{id}/resume`：按最新平台状态与expectedVersion重新授权。
- `POST /api/v1/optimization/history/{id}/recheck|acknowledge`：只读回查/确认人工核查。
- Engine `POST /api/v1/monitoring/external/observations:batch`：服务密钥认证，ID为字符串，金额Decimal字符串，时间+08:00。独立于旧模拟监控合同。
- Engine `POST /api/v1/monitoring/external/creative-jobs` 与 `GET .../{request_id}`：鉴权、租户隔离、不可变载荷与持久请求ID的生成和回查接口。

## 原调控动作与兼容

原手动接口和入口保留。`policy.tactics` 的五项有效权限默认全部关闭，旧配置反序列化也默认关闭，开发与更新服务不会替真实账户授权。

- 起量：控成本、连续成熟小时盈利至少消耗的20%，订单达到样本门槛；库存明确，且没有运行、暂停或状态不明的调控任务。
- 追投：同样检查计划利润；同时要求自建、审核通过、仍绑定的视频在连续2–7个成熟日均盈利，累计利润至少消耗的20%。
- 素材删除：按单素材净成交收入与对应商品贡献率估算，连续成熟日均亏损、累计损失达到亏损线，且达到消耗门槛。关联计划均须保留每商品指定数量的已审核可投视觉素材。
- 商品删除：按单商品净成交收入与已确认贡献率判断连续亏损，达到相同门槛；至少保留指定商品数。
- 素材新增：仅接受上文的新诊断生成与试投链路，旧候选复制机制已停用。`PRODUCT_ADD` 不在自动执行白名单，商品仅支持自动删除；旧 `productAdd=true` 读取为false，旧未提交新增提案不执行，已提交历史只允许只读回查。

实体日统计截止到 `observed_at − conversion_delay_minutes` 所在北京时间日期之前的完整日，逐日完整校验。缺净成交字段、产品关联不唯一、素材对象ID无法核实、未知审核状态时继续观察。视频、图片、图文有明确对象映射时可自动增删；标题与直播画面缺少可比净成交统计，不纳入自动删减，手动路径保留。

单次起量/追投预算最低100元（含100）、不得超过计划日预算，时长0.5–24小时且步进0.5。每计划每日追加预算单独授权，已提交任务按全额占用当天额度，包括结果不明的任务。账户预算检查还包含正在运行、可恢复的手动/自动调控任务预算。所有新增动作共享已有冷却与动作次数，风险暂停优先，每轮最多选一个新增动作。

App执行前独立重读实体利润、资格、库存、绑定和授权，固定参数构建平台请求；Engine不提供任意写入JSON。先持久化EXECUTING及执行意图，再提交。转投成员逐个解析自身素材ID，全部回查目标与其他保留绑定；部分生效、超时、中断时只读回查，不重复写入，超时后账户停止后续自动执行并通知人工核查。成功后更新显示数据与共享内容快照，原发布审计快照保持不变；后续重新创建转投计划使用核实后的最新共享绑定。

候选选择接口保持兼容并返回空列表。全店历史显示动作预算、时长、实体、生成来源、同步成员和回查结果，通知沿用现有盯盘通知流程。

## 素材场景档案与效果反馈（2026-10-13）

智能生成、上传后从素材库选择、千川已有投放素材，统一关联到具体商品和准确的平台素材对象。AI 生成方案保存在 Engine 素材内容的 `creative_profile`；App 在素材就绪后异步分析实际视频或图片，保存使用场景、风格、商品展示角度、人群、表达卖点、开头、讲述和音乐方向。生成方案与实际画面分析分开保存；文件名、标题和 URL 不作为场景事实。素材库优先复用同租户、同商品、同文件版本的已有档案，缺失时分析实际媒体。没有可读媒体或分析失败时显示待分析，不虚构标签，也不改变原素材审核和手动投放资格。

App 的 `material_creative_context` 保存档案、不可变素材版本、来源、生成描述、商品关联、平台对象和最新成熟效果评估。删除素材不删除档案。租户、广告账户、商品和对象 ID 均匹配后才将效果关联到档案；不靠名称匹配，也不从其他候选计划复制素材。历史方案和生成请求可追溯，素材页可查看场景档案并重试明确失败的分析。

Engine 每轮按完整成熟日统计、商品贡献率、退款预留、消耗门槛和亏损线评估素材为 LOSS、QUALIFIED 或 OBSERVING。只有实际画面分析可信度至少 0.6 且满足亏损条件的方向才用于规避；未分析、样本不足、手动删除均不算失败。相同标签下存在成熟盈利素材时保留成功证据；风格与角度按素材形式判断，商品真实使用场景可在不同形式之间参考。商品利润参数或评估阈值改变时，不沿用旧口径的失败结论。

自动追加的 `scene_strategy` 包含失败方向、成功方向和应优先规避的场景、风格、展示角度，进入生成任务约束及商品卡图片 prompt。测试疲劳素材的开头时保持原场景、风格和主要角度。自动追加先依据历史效果选择具体的场景、风格与商品展示角度，再以该方向编写文案、分镜和画面方案。在调用图片、视频、配音模型前核查完整文字方案，识别同义失败方向及标签与实际方案矛盾。方向是优先偏好，不是一票否决的产出门槛：没有合适候选或方向规划不可用时，优先参考同商品、同形式的成熟成功方向，否则从当前商品参考图可支持的外观表达中选择相对少冲突的备用方向，不虚构商品功能与使用效果。方向冲突先做一次文字调整；仍有冲突时按检查中的冲突项选择相对更合适的有效草稿继续生成，文字修订失败时保留上一次有效草稿。检查服务不可用时保留已选方向与规避提示继续生成，明确记录 `ADVISORY`，不得伪装成已通过检查。所选方向、检查记录和降级原因持久化，并在自动盯盘生成记录中展示。断点恢复复用同一方案；已有媒体提交时不能改变方向或重复付费。商品归属、授权、数量、技术规格及完整可执行方案检查仍保留，核心生成服务不可用时不能承诺生成成功。普通手动生成及人工修订不进入这项自动方向规划。生成后的实际素材分析和原发布条件保留；实际仍命中亏损方向时沿用人工审核路径。素材级效果只是试投证据，不承诺场景单因素因果关系，也不保证下一条一定盈利。人工明确审核的发布和原手动接口保留。
